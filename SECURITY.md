# Security Policy

## Supported Versions

We maintain `main`. Please base security reports on the latest commit.

## Reporting a Vulnerability

- Do not open a public issue for security vulnerabilities.
- Instead, email the maintainer privately or use GitHub Security Advisories if enabled.
- Provide a detailed description with steps to reproduce, impact, and affected areas.

If you cannot find contact information, open a minimal issue asking for a private security contact.

## Responsible Disclosure

We will investigate and respond as quickly as possible. If a fix is required, we will coordinate a release and credit reporters who wish to be acknowledged.

## Secrets

Do not include any real credentials in issues or PRs. Use environment variables as documented in `.env.example`.
